## 数据与安全设计

Flask+Waitress+本地HTML/CSS/JS，无Node构建链，禁止debug和公网监听。主库只用mode=ro读取，取完快照立即关闭连接；网页不初始化或迁移采集表。账号同目录的reader.sqlite3独立保存状态和反馈队列；反馈持久化后尝试获取原写入锁，繁忙则稍后同步，崩溃重试通过唯一事件标记防重。

状态按正文hash判断：正文更新后旧已读/不感兴趣不会静默覆盖新版本；收藏仍保留。原反馈与网页反馈合并展示，完整历史可恢复。原updated_at重复扫描刷新问题已修正；历史展示优先参考该版本投递记录的初次时间，避免把最近一次检查伪装成正文更新。

页面不加载外部图片、字体或JS，正文使用textContent按纯文本展示；原文/附件只允许http(s)链接，打开外站不传referrer。网页不调用模型，不提供学校凭据输入或任何密钥接口。

## Git安全集成

历史验收文档引用的实际联调JSON证据只保留本地，不随源码发布；唯一公开的评估JSON为虚构样本结果。真实通知、账号作用域和运行路径不会通过这些证据文件进入Git。

GitHub通过已有Git Credential Manager的正常浏览器流程授权，不索要或输出PAT。首次认证后确认目标仓库没有任何ref，保留原项目6个MIT提交；原origin重命名upstream，新origin指向用户指定仓库，没有force push或重置共享历史。

提交前检查全部可达历史和暂存树：禁止本地配置、数据库、会话、真实画像、备份、日志、实际通知fixture；对比本地安全库已保存凭据与常见密钥格式。原全部历史树逐一检查无违规，候选源码与脱敏文档人工检查。提交作者使用GitHub noreply邮箱，避免新增学校学号邮箱到提交元数据。

仓库包含Windows回归工作流（官方actions固定提交），仅运行虚构样本/本机组件测试，没有学校凭据或真实数据。GitHub Actions是否成功需以远程运行结果为准，不能用本机通过代替。
